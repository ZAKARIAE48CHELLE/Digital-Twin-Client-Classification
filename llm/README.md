# OSMOS Local LLM-Assisted Action Intelligence (Phase 5)

This directory implements the local LLM-assisted cognitive intelligence layer on top of PostgreSQL database tables and existing rule-based analytics.

---

## Architecture Flow

```
PostgreSQL historical data
        ↓
Existing analytics modules
        ↓
Rule-based alerts
        ↓
Local LLM assistant (Ollama API)
        ↓
Bilingual explanation + recommendation + admin guidance
        ↓
Admin validates / edits / ignores
        ↓
Action saved in PostgreSQL (llm_action_recommendations table)
```

---

## Model Recommendations

1. **Primary Model Target**: `Qwen3-8B GGUF Q4_K_M` (via Ollama `qwen3:8b`)
2. **Fallback Model**: `Llama 3.1 8B Instruct Q4`
3. **Fast Lightweight Option**: `Phi-4-mini-instruct`

## Ollama Setup Guide

To run the local LLM integration:

1. **Install Ollama**: Download and install Ollama from [ollama.com](https://ollama.com/).
2. **Pull the model**:
   ```bash
   ollama pull qwen3:8b
   ```
3. **Configure Environment variables** in your root `.env` file:
   ```ini
   OSMOS_LLM_ENABLED=true
   OSMOS_LLM_PROVIDER=ollama
   OSMOS_LLM_MODEL=qwen3:8b
   OSMOS_LLM_BASE_URL=http://localhost:11434
   OSMOS_LLM_LANGUAGE=fr_en
   OSMOS_LLM_TIMEOUT=120
   ```
4. **Launch OSMOS**:
   ```bash
   streamlit run app.py
   ```

## ⚡ Performance Optimization for Local LLMs

If `qwen3:8b` is too slow or triggers read timeouts on GPUs like the RTX 3070 (8GB VRAM), consider using a lighter model:

* **Recommended Fallbacks**:
  * `llama3.1:8b` (via `ollama pull llama3.1:8b`)
  * `phi4-mini` (via `ollama pull phi4:mini` or similar lightweight tag like `phi3:mini`)
* **Local Run Tips**:
  * **First Generation Delay**: The very first generation call can be slow (taking 30–60s) because Ollama is dynamically loading the GGUF weights into system/GPU memory. Subsequent calls will run much faster.
  * **Pre-load Model**: Start Ollama and run a quick test query via command line before launching OSMOS.
  * **Free VRAM**: Close other GPU-heavy applications (like game engines, intensive CAD tools, or open browser instances with hardware acceleration) to prevent Ollama from falling back to CPU execution.
  * **Prompt Sizing**: Keep simulation logs and context sizes reasonably short.

## Capabilities & JSON Response Format

Every recommendation generated by the LLM is returned and saved matching this exact structure:

```json
{
  "summary_fr": "...",
  "summary_en": "...",
  "risk_explanation_fr": "...",
  "risk_explanation_en": "...",
  "priority": "Low | Medium | High | Critical",
  "recommended_action_fr": "...",
  "recommended_action_en": "...",
  "suggested_channel": "Email | Phone | SMS | Dashboard Follow-up | Manual Review",
  "message_draft_fr": "...",
  "message_draft_en": "...",
  "admin_guidance_fr": "...",
  "admin_guidance_en": "...",
  "confidence": "Low | Medium | High"
}
```

If the LLM server goes offline, it fails over gracefully to a predefined fallback dictionary and writes a warning entry to the `audit_logs` table.
